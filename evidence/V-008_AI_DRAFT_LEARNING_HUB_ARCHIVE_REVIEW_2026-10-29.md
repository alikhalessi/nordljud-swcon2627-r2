## Scope and feasibility annotations (AI planning only, not part of the exact proposed prompt)

- **Information architecture:** Two main areas stay intact; four compact subviews live under Your Learning instead of four new top-level tabs.
- **Public archive vs personal record:** the same original 3 items can be recalculated for a past local date. Do not claim the user saw them. Explicit completion is only a self-report; the user can reverse it. First daily feature date 2026-10-29 prevents falsely branding previous days as having been published by the system.
- **Source version:** Historical selections remain grounded in the unchanged F04 daily algorithm and corpus; retain a version tag and stop claiming exact reproduction if future source/algorithm changes undermine it.
- **Review queue:** Distinct from favorites (interest), studied (intentional action), and completed lesson (self-report). Stable identity must include level + lemma + exact English meaning.
- **7/14-day quizzes:** rolling local-day eligibility rather than arbitrary calendar Sundays. They are offered when the learner opens My Review, not sent as pushes. Low scores can be used as evidence *only if actually recorded* and tied to the selected sense. Reuse the V-007 grounded practice engine and its honest limitations.
- **Persistence:** Current project source uses Supabase's browser client to read account-specific `nordljud_favorites`, `nordljud_studied`, and `nordljud_practice_history`. No existing schema/migration folder was found in the Vibe repository root; new user-record schemas and deployment must therefore be investigated, versioned and independently checked. Production migration deployment remains a second user authorization gate.
- **Security:** Supabase docs emphasize both Data API privileges/grants and database RLS, not just a UI-side `user_id` filter: https://supabase.com/docs/guides/database/postgres/row-level-security ; https://supabase.com/docs/guides/api/securing-your-api . Tests need a real supported two-identity environment; otherwise report `BLOCKED`.
- **Guest safety:** F03's existing browser guest preference key does not store scores/history. V008 would add a *separate* versioned local namespace with explicit opt-in actions and a clear-data facility, not silently modify or claim F03 guest preferences already sync.
- **Scope boundaries:** No changes to frozen curriculum, original benchmark or independent SDD branch. No PWA, Android push, scheduler, new grades/streaks or claims of validated memory science. Live browser and full DB security remain unverified until actual evidence is collected.
