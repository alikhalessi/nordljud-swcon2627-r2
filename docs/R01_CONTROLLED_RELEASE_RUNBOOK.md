## Reproducible CI and evidence control

- `package.json` pins exact direct dependency versions. Resolved lockfile is generated by real GitHub npm registry resolution, rather than manual fabrication; `npm ci` must pass on the runner and in any clean test environment. `npm install` is **not** an acceptable release verification because it can rewrite dependency resolution.
- `.github/workflows/vibe-first-check.yml` runs on isolated R01 work and pull requests targeting `condition/vibe`, as well as the legacy Vibe branch until Production policy is changed. Keep archived failures, logs and exact SHAs; do not rewrite RED evidence.
- Optional HTTP candidate smoke: `scripts/r01-candidate-smoke.mjs` checks an explicit immutable Vercel URL, HTTPS, successful HTML status and an app marker. It **prints NOT TESTED** if `R01_CANDIDATE_URL` is absent. A smoke PASS does **not** certify OAuth, RLS, browser navigation, mobile, semantics or real data persistence. For an exact SHA, check Vercel provider deployment metadata separately.
- For GitHub Actions, `R01_CANDIDATE_URL` must be a GitHub Actions variable pointing to the **exact candidate deployment URL**; setting an alias without proof of its SHA is not enough. If no candidate is available, report BLOCKED/NOT TESTED rather than silently bypassing the release requirement.
- RED test-first source checks and actual CI failures are preserved as academic events; excessive failure emails should be reduced by running WIP commits on isolated branches and using GitHub notification preferences, not by concealing failed workflows.
- Repo's historic README and frozen four Swedish datasets remain untouched. Never copy any Vibe implementation to SDD.
