# Moodle SWCON2627 report rubric — 35-mark evidence map

Based on the student's supplied Moodle project report description (last modified 31 Aug 2026). This is an evidence planning index, not an instructor-issued grade.

| Section | Max | Necessary evidence and report coverage |
|---|---:|---|
| 1. Introduction & Paradigm Shift | 3 | Project overview, Vibe approach, SDD approach and chosen toolkit, scope and timeline |
| 2. Requirements & System Specification | 6 | Stakeholders; FRs; measurable NFRs; stack and choices; UI/API contracts; how AI assisted requirements derivation |
| 3. Vibe Coding and Your Project | 5 | Actual prompting framework, genuine full significant prompts, iterations, errors, corrected exact prompts, outputs and failures |
| 4. Specification-Driven Development | 7 | Official toolkit and reason, environment/IDE/agent, SRS/constraints/interfaces/acceptance, actual workflow, implementation and original prompts |
| 5. Verification & Validation | 6 | Strategy incl. human/AI roles, code audit defects, test cases expected/actual PASS/FAIL and authentic logs/screenshots |
| 6. Project Management & AI Tools | 3 | Clear README, Git history, prompts/spec-linked commits, issue decisions, actual sole-student role and AI roles |
| 7. Reflections and Reusable SDD Workflow | 5 | Evidence-backed benefits/bottlenecks/lessons, measured timing **only if real**, reusable phases with diagram and human oversight |
| **TOTAL** | **35** | Executive summary 200–300 words; student details and actual contribution |

## Submission proof checklist
- Original prompt text or explicitly identified missing transcripts, **not** reconstructed perfect prompts.
- Git branches frozen at known commits; honest reproduction of actual test results.
- Screenshots must depict real tested browser states; label source and time.
- Diagram is rendered and understandable.
- Student ID entered in final report; individual submission approval and teacher private-repo read access verified.
- Actual final document exported in the required Moodle format (not established by the supplied report-description page).
- Correctly identify the coding agents used, toolkit CLI vs interactive skill execution and actual human approvals.
