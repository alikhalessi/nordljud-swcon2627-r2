## 3. Strong qualitative findings for comparison (hypotheses, NOT proven causal effects)
1. **Construct → Fixation cycles:** observed repeatedly (fixed single-word learning → explorer; independent modes → feedback; accordion → tabs; daily navigation → relocation; Google redirect → Preview env). Valid retrospective theme; **not** proof Vibe is inherently inferior to SDD.
2. **Human insight mattered:** user spotted UX/missing feature problems that source-level CI had not resolved; AI-generated tests also sometimes assumed clean data falsely.
3. **Approval provenance varied:** exact student-supplied V-001 and V-006 texts versus AI-written proposals approved by student and short feedback directly implemented. Distinguish each rather than claiming homogeneous prompting.
4. **Environment is a third variable:** Supabase provider, URL allowlist, Preview routing, Vercel quota, GitHub Free enforcement and protected Preview made release readiness harder even with passing source checks. SDD must face similar external checks to fairly compare.
5. **External verification gap:** largest remaining weakness is browser/manual F01–F15, two-account signed-JWT negative isolation and exact-endpoint smoke. Do not claim these as PASS for either methodology unless performed.
6. **Order/learning effects:** student learned vocabulary special senses, API and OAuth failure modes during Vibe. Any later SDD may benefit from human awareness even with independent code; acknowledge this confounder.
7. **Scope drift:** photos and all daily archive/review functionality were introduced late, despite the frozen common F01–F15. A controlled Scope Equivalence Matrix is necessary before SDD implementation.
